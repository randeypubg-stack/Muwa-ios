# Muwa: карта исходников

Актуальна для структурирования от 14 октября 2026, на основе Build 53.
Экран показывает данные и передаёт действия существующему владельцу состояния.
Оформление не управляет авторизацией, сетевыми запросами или геометрией навигации.

## iOS / iPadOS

`native-patches` содержит канонические заменяемые исходники. Неизменяемая основа
— `source-base/MuwaNativeBase.zip`. `scripts/assemble_ios.py` проверяет SHA-256,
применяет исходники и ресурсы, регистрирует каждый Swift-файл один раз и создаёт
полный Xcode-проект. Тот же скрипт используется локально и в CI.

| Папка | Ответственность |
| --- | --- |
| `Sources/App` | Запуск, корневой контейнер и переходы, CarPlay |
| `Sources/Models` | Трек и документы субтитров |
| `Sources/Services` | Каталог, AVPlayer, timeline, очередь, загрузки, auth, Premium, публикации |
| `Sources/Theme/DesignTokens.swift` | Общие цвета и размеры |
| `Sources/Theme/Typography.swift` | Системные шрифты и роли текста |
| `Sources/Theme/Motion.swift` | Общие параметры и политика анимаций |
| `Sources/Theme/AppBackground.swift`, `Theme.swift` | Фон и поверхности |
| `Sources/Theme/AdaptiveLayout.swift` | Единственный расчёт адаптивной геометрии |
| `Sources/Views/Components` | Обложки, бар, мини-плеер, строки и общие подписи |
| `Sources/Views/Home`, `Player`, `Library`, `Profile`, `Search`, `Premium` | Экраны соответствующей функции |
| `Resources` | Каталог ресурсов, включая цвет системного запуска |
| `Configuration` | Отдельный opt-in entitlement CarPlay |

Состояние жестов большого плеера остаётся в его существующем компоненте, а
воспроизведение — в `PlayerManager`. Дробление файлов не создаёт запасной
плеер или второй таймер. В portable-архиве `iOS` — производный готовый проект,
`Repository/native-patches` — место правок. Отдельных файлов шрифтов сейчас нет:
iOS использует системную типографику.

## Android

Корень Kotlin: `android/app/src/main/java/app/muwa/nasheeds`.

| Файл / папка | Ответственность |
| --- | --- |
| `MainActivity.kt` | Системное окно, разрешения и запуск Compose |
| `MuwaApp.kt` | Составление экранов и один расчёт нижних insets |
| `MuwaModel.kt`, `PlaybackService.kt` | Состояние приложения, Media3 и системная медиасессия |
| `Backend.kt`, `Downloads.kt`, `Diagnostics.kt`, `Data.kt` | Сеть, файлы и постоянные данные |
| `ui/design` | Цвета, шрифты, движение, reduced-motion policy, фон, layout tokens |
| `ui/navigation` | Верхний и нижний бар |
| `ui/components` | Общие элементы и мини-плеер |
| `ui/home`, `catalog`, `library`, `search`, `profile` | Каталог, подборки и личная библиотека |
| `ui/player`, `queue`, `playlists` | Плеер, очередь и диалоги плейлистов |
| `ui/account`, `settings`, `publication`, `launch` | Аккаунт, настройки, публикация и запуск |
| `ui/state` | Общие утилиты сохранения/применения состояния UI |

Управление маршрутами, открытым плеером и диалогами остаётся в одном корневом
компоненте. Gradle wrapper, плагины и зависимости закреплены в проекте.
Android использует системный SansSerif, а не вложенный коммерческий шрифт.

## Backend и панель

`backend/endpoints` — HTTP-контракты; `backend/helpers` — сервисы авторизации,
каталога, файлов, квот, Premium и субтитров. `backend/runtime/server.ts` подключает их к
runtime. SQL-файлы — схема и последовательные миграции. Рабочая база Beget
создана заново по решению владельца; приложение не требует старых данных Floot.

В `admin-panel/features` находятся `workspace`, `catalog`, `captions`, `submissions`.
`useAdminWorkspace` остаётся единым владельцем фильтров, запросов и mutations.
`components` — входной компонент и общие контролы; `helpers` — API и utilities.
`styles/tokens.css` хранит цвета/spacing, `typography.css` — роли шрифта,
`motion.css` — длительности переходов. CSS Modules привязаны к соответствующему
компоненту. Имена Inter Tight/Instrument Serif пока используют CSS fallback:
бинарники этих шрифтов не поставляются и внешние загрузки не добавлялись.

`tools/local-asr` — один локальный Whisper worker и валидация текста/таймингов.
Любое распознавание создаёт приватный черновик. Общий код публикации не публикует
его автоматически. `tools/telegram-import` и `telegram-bot` — существующий
импорт; доступ владельца проверяется сервером.

## Правила сопровождения

1. Читать `AGENTS.md`, `docs/CURRENT_STATE.md` и README нужного модуля.
2. Исправлять канонический компонент и его вызовы, сохраняя владельца состояния.
3. Изменения шрифтов/анимаций делать в системе оформления, функциональные —
   в сервисе или feature. Не менять утверждённую навигацию без запроса владельца.
4. Проверять затронутые контракты, сборку и доступность; датировать доказательства.
5. Генерировать исходный архив из чистого Git-коммита и проверять восстановление.
