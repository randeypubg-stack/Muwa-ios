# Muwa: структура приложения

Обе платформы остаются нативными: SwiftUI/AVPlayer и Kotlin/Compose/Media3.
Экран не содержит второй движок воспроизведения или запасную реализацию сервиса.
Идентификатор приложения, существующий backend и ключи пользовательских данных
сохраняются при разделении файлов.

## iOS

`native-patches` — исходники замен, а не второй Xcode-проект. CI проверяет
`source-base/MuwaNativeBase.zip`, заменяет исходные файлы и регистрирует добавленные
файлы через `scripts/prepare_native_extras.py`. Полный Xcode-проект находится
в артефакте Full Source. Его папки:

Архив содержит готовый `MuwaNasheedsNative` и точный снимок всех отслеживаемых
исходников в `Repository`. Android находится в `Repository/android`; там же
сохранены backend, панель, проверки и все CI workflows. Локальные кэши сборок,
учётные данные и закрытые QA-артефакты в архив не попадают.

| Папка | Роль |
| --- | --- |
| `Sources/App` | Запуск, переключение вкладок, переход плеера, CarPlay |
| `Sources/Models` | Трек, аккаунт, публикация, документ субтитров |
| `Sources/Services` | Воспроизведение, timeline, каталог, загрузки, auth, Premium, диагностика |
| `Sources/Theme` | Палитра и размеры (`DesignTokens`), шрифты (`Typography`), движение (`Motion`), фон (`AppBackground`), поверхности (`Theme`) |
| `Sources/Views/Components` | Общие строки треков, обложки, заголовки, форматирование подписей |
| `Sources/Views/Home` | Главная и реальные подборки каталога |
| `Sources/Views/Player` | Плеер, очередь, строка очереди и субтитры |
| Остальные `Sources/Views` | Библиотека, профиль, поиск, авторизация и Premium |

Новые Swift-файлы регистрируются один раз. Проверка регистрации запускает
подготовку повторно и проверяет сохранение iPhone-сцены и CarPlay-сцены.

## Android

Путь исходников: `android/app/src/main/java/app/muwa/nasheeds`.

| Файл или папка | Роль |
| --- | --- |
| `MainActivity.kt` | Системное окно, разрешения, запуск Compose |
| `MuwaApp.kt` | Навигация, общий контейнер, мини-плеер, связывание действий экранов |
| `MuwaModel.kt` | Единственный владелец состояния приложения и связи с Media3 |
| `PlaybackService.kt` | Системная медиасессия и Android Auto |
| `Backend.kt`, `Downloads.kt`, `Diagnostics.kt`, `Data.kt` | Сеть, файлы, диагностика, постоянные пользовательские данные |
| `ui/design` | `MuwaColors`, `MuwaTypography`, `MuwaTheme`, `MuwaMotion`, `AmbientBackground` |
| `ui/components` | Обложка, строка трека, общая кнопка, подписи |
| `ui/home`, `ui/queue`, `ui/search`, `ui/library`, `ui/profile` | Отдельные экраны соответствующих функций |
| `AccountScreens.kt`, `PublicationScreen.kt`, `PlayerScreen.kt` | Существующие аккаунт, загрузка публикаций и плеер |

Kotlin-файлы изменённых экранов оформлены ktfmt в стандартном стиле Kotlin.
Цвета и шрифты меняются в системе дизайна, состояние — в существующем сервисе,
композиция и события — в соответствующем экране.

## Правила изменений

- Найти реальный источник и его вызовы; изменить его, обновив импорты и регистрацию.
- Не добавлять параллельный класс, backend, очередь, Premium или playback state.
- Сохранять совместимость данных, миграции и намеренно отложенные функции.
- Проверять навигацию и действия отдельно от внешнего вида; скриншот не доказывает
  качество жеста, доступность VoiceOver или частоту кадров физического устройства.
- Редизайн не включает оплату ASR и не возвращает Premium-блокировки в закрытом тесте.
