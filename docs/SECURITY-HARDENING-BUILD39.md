## Загрузки и доступ к медиа

Выдача presigned PUT требует серверной сессии. Владелец определяется из сессии,
а не из присланных ID/email. Квоты резервируются до выдачи URL и сериализуются
блокировкой строки аккаунта, включая одновременно пришедшие запросы.

| Режим | Заявки/час | Незавершённые заявки | Резерв за 24 часа | Общий резерв |
|---|---:|---:|---:|---:|
| Пользовательские публикации | 30 | 5 | 512 MiB | 1 GiB |
| Публикации администратора | 200 | 100 | 5 GiB | 20 GiB |
| Загрузка каталога администратором | 200 | — | 5 GiB | 20 GiB |

Квоты двух административных каналов независимы. Они заданы только на сервере
в `uploadSecurity.tsx`. Для файлов доступны MP3, M4A, WAV; для обложек — JPEG,
PNG, WebP. Максимум: аудио 100 MiB, обложка 10 MiB, заявка JSON 256 KiB.

Новые файлы сохраняются в **private** storage, включая черновики каталога.
Каждая версия аудио/обложки имеет случайный отдельный ключ. PUT требует
`ifAbsent`; оба мобильных клиента передают выданные SDK заголовки. Повтор с
тем же SHA-256 переиспользует файл; после резервирования финальной заявки её
содержимое заморожено. iOS сохраняет дату заявки и сериализует JSON в стабильном
порядке для повторной отправки. API ошибок не возвращает сообщения SDK/SQL.

Сервер потоково проверяет фактический размер, ETag, SHA-256 и контейнер файла.
Проверяются сигнатуры форматов и пределы размеров изображения. Это **не полный
декодер аудио, антивирус или проверка качества нашида**. Публикация по-прежнему
проходит модерацию. Снимок принятого файла сохраняется; перед просмотром и
копированием в каталог проверяется соответствие снимку, а перед одобрением —
хеш скопированного файла. Заявка без существующего владельца не импортируется.

Каталог хранит постоянный `/_api/catalog/media` URL с версией файла. Endpoint
проверяет статус и права; опубликованный бесплатный нашид доступен слушателям,
черновик/архив — администратору. Байты и Range обслуживает хранилище после
редиректа. Срок GET аудио учитывает длительность, минимум час; обложки — пять
минут. Уже выданная временная ссылка действует до истечения срока. Скачанные
ранее опубликованные байты невозможно отозвать с чужого устройства.

В панели предусмотрена очистка просроченных планов, незавершённых публикаций
старше 48 часов и старых версий повторных загрузок. Под блокировкой повторно
проверяются ссылки на файлы. Материалы на проверке и используемые версии не
удаляются. Уборка вызывается администратором; автоматический scheduler на Floot
пока не настроен. Учёт старых, ранее загруженных файлов требует backfill.

## Клиент, панель и журнал ошибок

iOS-авторизация обращается к выбранной среде один раз, без отправки того же
пароля на запасной backend при 404/503 или обрыве сети. Sandbox выбирается
только явно через DEBUG + MUWA_USE_SANDBOX. Старые cookies production/sandbox
очищаются при выходе, даже если сеть недоступна. Сохранённый preferredBackend
не позволяет подменить выбранную среду.

POST панели, Premium, публикаций и subtitles v2 проверяет Content-Type,
Origin и Sec-Fetch-Site. Лимит JSON действует во время чтения байтов, до полной
загрузки и разбора. Панель не показывает логин и управляющие элементы в iframe.
**Это дополнительная клиентская защита; hosting-заголовок frame-ancestors ещё
не установлен.** Для production HTML нужен `Content-Security-Policy:
frame-ancestors 'none'` и/или `X-Frame-Options: DENY` через конфигурацию Floot.
Meta-тег не заменяет эти заголовки.

Удалённая диагностика выключена по умолчанию. При её включении и входе в аккаунт
передаются только UUID события, время, фиксированные категории/код ошибки,
платформа и версия сборки. Нет текстов запросов, URL, паролей, промокодов,
пользовательских текстов, stack trace или полных MetricKit payload. Очередь
ограничена 200 событиями и привязана к аккаунту; при смене аккаунта очищается.
Отправка идёт при новых событиях/возвращении к приложению; постоянного фонового
сервиса доставки нет. Полные отчёты доступны лишь для явного локального экспорта.

Сервер принимает максимум 20 событий в запросе, 15 запросов на аккаунт в сутки
и 1 000 запросов суммарно в сутки. UUID предотвращает повторные записи. Журнал
в панели доступен только администратору и показывает последние 14 дней.
Физическое удаление старых записей выполняется при приёме следующего отчёта;
для строгого срока хранения нужен отдельный ежедневный scheduler до внедрения.

Release Android использует R8 и удаление неиспользуемых ресурсов. Классы и
методы переименованы; пакет приложения сохранён для фильтра локальных отчётов.
Mapping хранится отдельно в частных артефактах CI. Обфускация усложняет анализ,
но не делает установленное приложение источником доверия или недоступным для
декомпиляции. Секреты и решения о правах должны оставаться на сервере.

## Исходники и CI

База Xcode перенесена в `source-base/MuwaNativeBase.zip`; SHA-256 совпадает с
исходной подтверждённой базой. CI больше не скачивает исходники с public CDN.
Повреждённый неиспользуемый `native-source.zip` удалён. Шаблоны игнорируют .env,
ключи подписи, credentials и локальные отчёты. Actions закреплены на commit SHA;
checkout не сохраняет credentials. Сборки требуют успешную проверку
исходников/архивов через Gitleaks. Владелец явно согласовал публичный GitHub
2 октября 2026; проверка видимости Private удалена из CI. Исходники намеренно
публичны, учётные данные и ключи в Git не сохраняются. Новые исходники не отправлялись
в сторонний сервис анализа.

Gitleaks 8.30.1 проверил всю локальную историю Git и текущие исходники с архивом
базы. Пять исторических и одно текущее срабатывание были точным выражением SQL
с полями lease_token/lease_until и ключевым словом EXCLUDED. В конфигурации исключён
только этот match в этом файле; остальные правила остаются включёнными.
После проверки исключения — 0 находок. Это результат конкретного сканирования,
а не доказательство отсутствия любых возможных утечек.

Codex Security предложен через Plugin Management. Подключение пользователем
не подтверждено; сканирование этим плагином не заявляется выполненным.

## Что препятствует внедрению

1. Публичный GitHub `randeypubg-stack/Muwa-ios` согласован владельцем;
   он больше не препятствует отправке исходников и запуску CI. Приватные
   репозитории тоже доступны при предоставленных интеграции правах, но менять
   видимость против выбранного владельцем режима не требуется.
2. Floot исчерпал дневной лимит developer actions; заявленный сброс —
   **3 октября 2026, 00:00 UTC**. Запись файлов, SQL, VM, typecheck и publish
   недоступны. Обход квоты и платное расширение не выполнялись.
3. Поэтому тестовый администратор id 9 пока не отозван по последнему известному
   состоянию. Реальный владелец — id 1, `randey.pubg@gmail.com`; его нельзя
   затронуть. Точный SQL уборки и список QA-файлов подготовлены локально ранее.
4. Старые public черновики ещё не удалены/перенесены. Удаление не отзывает уже
   скачанные сторонние копии. Старый публичный архив исходников соответствует
   выбранному владельцем режиму; его удаление не является условием работы CI.
5. Полный Floot auth пока недоступен для анализа: hashing, login/reset limiter,
   cookie flags, rotation/revocation, MFA и защита от перечисления аккаунтов
   не подтверждены. Их нельзя заменять придуманной схемой без чтения реального
   кода и сохранения существующих паролей/сессий.
