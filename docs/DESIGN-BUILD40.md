# Muwa build40: фон, Главная и очередь

Исходные экраны получены заново из CI build39, commit
`29d05de86652076d19f81ac0a95084f01920c666`: iOS run `37048834249`, Android
run `37048834161`; обе сборки и исходная проверка секретов успешны.
Снимки сняты нативными Simulator/Emulator, без браузерной подмены приложения.

## Исходная проверка

1. iPhone, Главная: реальные подборки открываются, но три большие одинаковые
   строки занимают почти весь первый экран; свет в фоне визуально отсутствует.
2. iPhone, очередь: отдельные удаление/drag доступны, но заголовок выглядит
   тяжёлым, активная строка определяется жёлтой иконкой, размеры удаления малы.
3. Android, Главная: первый экран состоит из повторяющихся строк; подборки
   находятся ниже полного списка, оформление не совпадает с iOS.
4. Android, очередь: после каждого трека повторяются три текстовые кнопки,
   которые занимают много места и визуально конкурируют с названием нашида.

Снимки сохранены в `/workspace/artifacts/Muwa-design-review/before` вместе с
исходными артефактами. Они показывают визуальный результат; работа экранного
диктора и физика свайпа требуют отдельной проверки на устройстве.

## Реализация

- Общая серебристо-синяя палитра, семантические системные шрифты и размеры.
- Три мягких радиальных световых пятна с медленным движением. Фон не использует
  playback clock и большой live blur; анимация останавливается вне активной
  сцены, при ограничении движения и энергосбережении.
- Подборки по длительности имеют настоящие обложки, число треков и переход
  к соответствующему каталогу. При крупных шрифтах карточки переходят в колонку.
  Первый просмотр iPhone выявил неверное измерение ideal size в ViewThatFits:
  обычный текст тоже включал колонку. Выбор двух колонок теперь зависит от
  реальной ширины контента; текст переносится внутри карточки.
- «Откройте для себя» ограничен двенадцатью треками; полный каталог остаётся
  в «Все». iOS использует ленивую горизонтальную загрузку.
- Очередь показывает активное состояние, компактные кнопки, длительность,
  плавное удаление/перестановку и способы изменения порядка для доступности.
- Снимки Android выявили чёрный текст на прозрачных поверхностях Material:
  тёмная палитра сама не задавала `LocalContentColor`. Цвет текста установлен
  в единственной теме приложения. Две похожие горизонтальные иконки очереди
  заменены на различимые минус и три линии.
- При выделении файлов сохраняются существующие владельцы данных и жестов
  плеера. Архитектура описана в `docs/ARCHITECTURE.md`.

и сохранение перестановки/удаления очереди. Снято 26 PNG на каждом размере,

Все три проверки холодного запуска тоже проходят. Guest MediaCodec recording
вызывал сбой hosted emulator после включения анимаций; запись переведена на

MP4 — копия для просмотра с сохранением времени. Нормальный запуск проверяется
по свежей UI hierarchy во время записи, отключённые анимации — отдельным
холодным запуском. PNG остаются в разрешении устройства, настройки возвращаются.

iOS run `37080911175` (№97), commit
`52588daeab894c21a31af86a289ab90170c543fe`: Release arm64 IPA и Debug Simulator
скомпилированы; regression checks, 45 backend checks и скан секретов проходят.
Регистрация источников идемпотентна, каждая реализация компилируется один раз.
Принятый обзор того же run содержит 17 PNG на каждом из четырёх
размеров: iPhone 16 Pro/Pro Max, iPad Pro 11/M4 и iPad mini/A17 Pro, всего 68.
Все девять заданий run №97 завершились успешно, включая подключение настоящей
сцены Muwa CarPlay и оригинальный снимок 800×480. CarPlay проверяется через

При подключении CarPlay обновляет общий каталог даже без окна телефона.
Сборка №89 исключена из выдачи: UI-проверки обнаружили нарушение

покупки и физический CarPlay требуют соответствующей конфигурации и устройств.
Защита сервера размещена 3 октября 2026 в существующем Floot production.
Миграция, реальные загрузки и авторизация проверены; все временные QA-аккаунты
и файлы удалены. Результаты и оставшиеся ограничения хостинга записаны в

не менялись; Full Source дополнительно включает финальные серверные изменения,
документацию и автоматизацию нативного обзора.

В последующем run №98 сборка, backend, экраны iPhone/iPad и CarPlay проходят;
завершение записи iPhone не проходит и при точечном повторе. Артефакт показывает,
что рекордер продолжал писать после SIGINT. Запуск записи теперь использует
разрешённый xcrun путь simctl, отдельный управляющий терминал и обычный Ctrl+C;
сигналы дочернего процесса восстанавливаются перед exec. Проверка реального
сигнала при наследованном SIGINT=IGNORE проходит локально. macOS проверяется в
`review-native-launch.yml` на готовом Simulator artifact: общий проверяющий
модуль сверяет все нативные входные файлы с Full Source. Тот же модуль используется
CarPlay; код проверки snapshot больше не продублирован в workflow. Отсутствующая
или незавершённая запись по-прежнему проваливает проверку, а не выдаётся за успех.
