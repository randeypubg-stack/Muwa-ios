
## Развёрнутые службы

- `/srv/muwa/current` указывает на `/srv/muwa/releases/beta-20261004`.
- `muwa-api.service`: Node.js 22, непривилегированный пользователь muwa, loopback
  127.0.0.1:3000, pool PostgreSQL 5 соединений, предел памяти 768 MiB.
- PostgreSQL 18: база muwa, 21 таблица; отдельный владелец схемы и роль приложения
  без прав суперпользователя/CREATE. База muwa_audit используется только тестами.
- Статический bundle панели доступен nginx: каталоги 0755, файлы 0644;
  приватные backend.env и media сохраняют отдельные закрытые права.
- nginx: только HTTPS-панель, API и подписанные запросы к файловому хранилищу.
  База и Node не слушают публичные интерфейсы. Сессии HTTP-only/Secure,
  изменения проверяют Origin и ограничение размера/частоты запросов.
- `/var/lib/muwa-app/media`: закрытое хранилище аудио/обложек на NVMe. База хранит
  метаданные, не сами аудиофайлы. PUT проверяет тип, длину и SHA, файлы неизменяемы;
  воспроизведение поддерживает Range/HEAD и временные подписанные ссылки.
  Максимум объекта 100 MiB, одновременно четыре загрузки, резерв диска 5 GiB.
- Серверные секреты `/etc/muwa/backend.env` доступны только root и не попадают в Git.
  Журналы nginx не содержат query-параметров подписанных ссылок или cookies.
- `muwa-cert-renew.timer`: проверка продления дважды в день с перезагрузкой nginx.
  Короткоживущий IP-сертификат требует исправного таймера; проверена настоящая
  пробная процедура продления в staging Let’s Encrypt.
- `muwa-backup.timer`: ежедневный pg_dump и снимок неизменяемых медиа, семь поколений.
  Снимки используют hard links, чтобы не копировать весь каталог каждый день.
  Восстановление dump проверено в отдельной временной базе: 21 таблица,
  без изменений рабочей базы. Это локальная копия на том же диске, не защита
  от потери VPS/диска.

SSH, UFW, Fail2ban и удалённый агент сохранены. Перезагрузка не выполнялась.
Текущие ресурсы 2 CPU / около 4 GiB RAM / около 38 GiB NVMe рассчитаны на личную
бету. Ёмкость для 10 000 зарегистрированных пользователей не доказана; до массового
запуска нужны нагрузочные измерения, план доставки медиа и внешние резервные копии.

## Функции и проверка

Панель использует существующие обработчики загрузки, черновиков, публикации,
модерации, ручных субтитров и журнала изменений. Автоматическое распознавание
приостановлено; загрузка и публикация от него не зависят. Premium-блокировки
в клиентах отключены для функционального тестирования. Apple/Google production
billing ещё требует настройки.

Проверено: 20 unit-спецификаций backend; 52 PostgreSQL-спецификации на disposable
базе; 30 реальных HTTP-проверок первого входа, сессий, беты, загрузки, публикации,
перемотки, ручных субтитров и diagnostics. На рабочем HTTPS проверены private PUT,
чтение/Range/hash, запрет анонимного доступа и отсутствие доступа к исходникам/.env.
Тестовые файлы удалены; проверка не создавала настоящий аккаунт владельца.
Панель первого входа и обычного входа реально открыта браузером по HTTPS на
1440×1000, 390×844 и 834×1112: без JavaScript-ошибок и горизонтального переполнения.
Проверены открытие одноразового фрагмента в уже открытой вкладке и его удаление
из адресной строки; при съёмке использован нерабочий тестовый фрагмент.

Нативные клиенты переключены на один Beget origin: iOS build 43 и Android build 41.
Защищённое аудио и обложки используют ту же cookie-сессию, что API. Старый Floot
каталог не подмешивается; демонстрационные треки находятся только в review fixtures.
Android debug и instrumentation APK компилируются, unit tests проходят локально.
iOS build 43 прошёл GitHub Actions run 109 (37201734663): Release arm64, regression,
четыре размера экранов, запуск с ожидающей сессией, реальные действия очереди и
плейлистов, подключённая сцена CarPlay и кадр внешнего дисплея 800×480.
В review используется локальное PCM-аудио: старый Floot CDN не участвует в этой
проверке. На физическом автомобиле ещё требуется Apple CarPlay provisioning.
Для Android заставка ограничена тремя секундами, чтобы потерянный callback
рендерера не скрывал уже смонтированную главную страницу. Проверка обновлённого
запуска и режима без анимаций на трёх размерах выполняется отдельно от записи
видео. На hosted GPU видеозапись приводила к зависанию/offline эмулятора;
поэтому она запускается явно через `record_launch_video` в Android workflow и
при запросе остаётся строгой проверкой, а не превращает сбой в успешный результат.

Для контроля: `systemctl status muwa-api nginx postgresql`, `journalctl -u muwa-api`,
`systemctl list-timers muwa-cert-renew.timer muwa-backup.timer`. Секреты и одноразовую
ссылку при диагностике не выводить в общие журналы.
