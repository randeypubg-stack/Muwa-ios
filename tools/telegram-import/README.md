# Muwa: импорт из Telegram

Импортёр работает на сервере или компьютере владельца. Он использует существующую
Muwa-авторизацию, `/_api/admin/action`, private presigned PUT и общий каталог.
Новые нашиды появляются **черновиками** в существующей панели. После проверки и
публикации их получает обычный каталог iOS, Android и CarPlay. Telegram не является
источником потокового аудио для приложения: сохраняется собственная копия файла.

## Владелец: запуск канала @muwa144 на Beget

На сервере подготовлены отдельный пользователь `muwa-import`, приватная папка
состояния и сервис `muwa-telegram-import.service`. Пока Telegram не авторизован,
сервис не запущен. Одноразовую настройку владелец выполняет в своём Termius:

```sh
/srv/muwa/telegram-import/.venv/bin/python /srv/muwa/telegram-import/setup-owner.py
```

В `my.telegram.org` → **API development tools** создайте собственные API ID/hash.
Команда попросит эти значения, пароль аккаунта Muwa, затем телефон, Telegram-код
и при необходимости 2FA. Вводить их нужно только в своём терминале, не в чате.
Она проверяет права Muwa и доступ к выбранному каналу, сохраняет конфигурацию
root-only 0600 вне репозитория и включает наблюдение за историей/новыми файлами.
Сервис получает настройки через systemd `LoadCredential`, работает без root и
может записывать только свою приватную папку. По умолчанию язык `und`:
это не ошибочное утверждение, что каждый нашид арабский.

Импорт доступен **одному серверному user ID**, заданному `MUWA_TELEGRAM_OWNER_ID`
в `/etc/muwa/backend.env`. Это ID авторизованной серверной сессии. Email или роль,
присланные клиентом, не дают права. Обычные пользователи и другие администраторы
получают 403; отсутствующая/некорректная настройка запрещает импорт всем.

Проверка и публикация черновиков: **https://93.188.187.96/admin**.
Остановить: `systemctl stop muwa-telegram-import`.
Статус: `systemctl status muwa-telegram-import --no-pager`.
Продолжить с сохранённого места: `systemctl start muwa-telegram-import`.
Чтобы отключить запуск после перезагрузки: `systemctl disable --now muwa-telegram-import`.
Отзыв Telegram-сессии в настройках Telegram также закрывает доступ импортёру.

Есть два способа получить исходники:

- JSON-экспорт **одного канала** из Telegram Desktop с включёнными аудиофайлами.
  Подходит для первоначальной истории без Telegram-сессии на сервере.
- MTProto/Telethon: история выбранного канала и режим наблюдения за новыми
  сообщениями. Требуется существующий Telegram-аккаунт с доступом к этому каналу
  и API ID/hash из `my.telegram.org`. Обычный Bot API не выдаёт прошлую историю.
  Импортёр не вступает в каналы, не читает остальные диалоги и не отправляет сообщения.

## Что сохраняется и проверяется

- MP3, M4A и WAV до 100 МиБ; другие сообщения, видео и голосовые заметки пропускаются.
- Реальная длительность/контейнер через ffprobe. Теги файла первичны, затем
  метаданные Telegram; неизвестный исполнитель прямо помечается для проверки.
- Встроенная обложка извлекается через ffmpeg; для экспорта поддерживается
  thumbnail. Соседняя фотография не назначается нашиду по догадке.
- Язык задаётся вручную (`--language ar`); по умолчанию `und`, не определён.
- Канал и ID сообщения связываются с постоянным ID каталога. Проверяется SHA-256
  **загруженных байтов**, а не присланное клиентом утверждение. Повтор одного
  сообщения и одинаковый файл в другом сообщении не создают новую запись.
- Новые обычные загрузки/одобрения тоже сохраняют проверенный fingerprint.
  Старые static-треки не имеют хеша: для сравнения с ними нужен отдельный backfill
  реальных байтов. Равное название или другая кодировка/ID3 не доказывают дубликат.
- Повтор после потери ответа возвращает тот же track ID. Изменившийся файл в
  уже импортированном сообщении получает 409; исправленные владельцем метаданные,
  субтитры и статус не перезаписываются. Разные записи с одним названием сохраняются.
- Private PUT и сессия Muwa используют разные HTTP-клиенты. Cookies/пароль Muwa
  не отправляются на URL файлового хранилища. Перенаправления HTTP отключены.
- Локальный SQLite-учёт сохраняет ошибочные задания отдельно от курсора истории.
  После перезапуска они остаются доступны для повтора. Один процесс удерживает
  файловую блокировку; дедупликация между серверами обеспечивается PostgreSQL.
- Работа последовательно ограничена партиями и паузой минимум 20 секунд между
  файлами. Существующие лимиты Muwa (в том числе 200 admin-загрузок/час) сохранены.

Автопубликация и автоматическое распознавание субтитров не включены. Пост/описание
Telegram не объявляется синхронизированным текстом. Привязка к проверенному аудио
и его хешу пригодится будущей очереди распознавания после завершённой загрузки.

## Подготовка backend

1. Сделать резервную копию существующей БД.
2. Применить `backend/telegram-import-migration.sql` **после** admin/security
   migrations, до обновления обработчиков. Миграция добавляет две таблицы и индексы,
   не создаёт аккаунты и не выдаёт права.
3. Разместить обновлённые `adminValidation.tsx`, `adminService.tsx`,
   `telegramImport.tsx` и метки событий панели в существующей среде Muwa.
   Обычные save-track/approve-submission теперь записывают fingerprint, поэтому
   миграция обязательна и для них. Telegram SDK нужен только отдельному импортёру.
4. Проверить admin lookup до скачивания файлов. CLI делает этот preflight сам.

Backend, авторизация и приватное хранилище уже работают на Beget с новой базой,
выбранной владельцем. Floot и перенос старых данных для импорта не требуются.

## Установка и первый локальный просмотр

Нужны Python 3.11+, FFmpeg/ffprobe и Linux/macOS (файловая блокировка POSIX).
Устанавливать от отдельного пользователя, которому принадлежит папка состояния.

```sh
python3 -m venv .venv
.venv/bin/pip install ./tools/telegram-import
.venv/bin/muwa-telegram-import export /path/to/channel/result.json \
  --state-dir /path/to/private/muwa-import --language ar
```

Без `--upload` команда только проверяет локальные файлы и записывает `ready`.
Она не входит в Muwa, не арендует ресурсы и не вызывает платные сервисы.
JSON нужно экспортировать вместе с аудио; HTML-экспорт не подходит.

Для реальной загрузки после размещения backend:

```sh
.venv/bin/muwa-telegram-import export /path/to/channel/result.json \
  --state-dir /path/to/private/muwa-import --language ar \
  --backend https://your-muwa-backend.example --upload
```

Email/пароль существующего администратора вводятся локально; пароль скрыт.
Команда по умолчанию обрабатывает 100 файлов. Повторите её для следующих партий;
уже завершённые source IDs пропускаются. `--recheck` снова проверяет байты экспортных
сообщений, сохраняя запрет на автоматическую замену ранее импортированного нашида.
Отчёт содержит счётчики; код возврата 1 означает ошибки/требуемое вмешательство.
Неполные экспортные файлы, чужие пути и symlink вне экспорта не загружаются.

## История и новые сообщения через Telegram API

Настроить `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в защищённых настройках машины
или отдельном EnvironmentFile с правами 0600 вне Git. Не вставлять реальные значения
в команды, историю shell, чат, мобильный клиент или архив исходников.

```sh
.venv/bin/muwa-telegram-import telegram-login --state-dir /path/to/private/muwa-import
.venv/bin/muwa-telegram-import telegram @channel_username \
  --state-dir /path/to/private/muwa-import --language ar
```

Первый вход запросит телефон, код и при необходимости 2FA в вашем терминале.
Файл `telegram.session` даёт доступ к Telegram-аккаунту: хранится только в закрытой
папке 0700, сам файл 0600, исключён из Git и архивов. Для сервера разумно выделить
отдельный Telegram-аккаунт с доступом только к нужному каналу.

Однократная команда смотрит до 500 сообщений и проверяет до 100 аудиофайлов.
Повторы продолжают историю от сохранённого курсора. Для постоянного наблюдения:

```sh
.venv/bin/muwa-telegram-import telegram @channel_username \
  --state-dir /path/to/private/muwa-import --language ar \
  --backend https://your-muwa-backend.example --upload --watch
```

В режиме сервиса параметры Muwa берутся из защищённой конфигурации
`MUWA_IMPORT_BACKEND`, `MUWA_IMPORT_EMAIL`, `MUWA_IMPORT_PASSWORD`; сессия Telegram
создаётся заранее интерактивно. Не передавать пароль аргументом процесса.
Обычный Telegram-бот без аккаунта не подходит этому MTProto-клиенту.
При отзыве доступа/401/403 процесс останавливается. Для больших FloodWait
наблюдение ждёт и повторяет чтение; логи сохраняют только коды, без SDK-запросов.
Скачанные временные аудио удаляются после upload-попытки даже при ошибке.
Неиспользованные частные upload-lease удаляются обычной уборкой Muwa.

## Проверено и ещё не выполнено

Backend/PostgreSQL и Python checks проверяют
реальный ffprobe/WAV/MP3/M4A, извлечение тегов и встроенной обложки,
параллельные импорты, потерю ответа, повреждённые файлы,
возобновление, смену провайдера и изоляцию HTTP-only cookies от storage.
CI: `.github/workflows/telegram-import.yml`; тесты используют временную БД
`muwa_audit`, контролируемые storage/Telegram ответы и не входят в чей-либо аккаунт.

**Живой импорт требует одноразовой авторизации владельца**. Канал выбран:
`@muwa144`; автоматическое распознавание отложено. Прошедшие тесты не подтверждают
живую Telegram-загрузку или качество каждого ещё не импортированного нашида.
